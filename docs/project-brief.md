# NightMarket 插件使用说明书 — 项目简报

## 问题陈述

Claude Code 的 Night Market 生态包含 23 个功能强大的插件（abstract、attune、leyline、pensive、phantom、scry 等），覆盖项目开发全生命周期。然而，这些插件缺乏系统性的中文使用文档，导致：

- 用户不知道每个插件的具体功能和使用方式
- 缺乏典型场景的最佳实践指引
- 新用户上手门槛高，需要逐个摸索
- 插件之间的协作关系不清晰
- 缺乏可复用的文档模板，难以持续维护

## 目标

1. 为全部 23 个 Night Market 插件编写详细中文使用说明书
2. 构建 VitePress 静态文档站点，部署至 GitHub Pages
3. 每个插件包含：命令解释、使用格式、使用场景、实际案例
4. 使用 phantom + scry 插件制作截图和终端录屏
5. 建立文档模板规范，确保风格一致、便于后续维护

## 成功标准

- [ ] 23 个插件全部拥有独立文档页面
- [ ] 每个插件页面至少包含 2 个实际使用案例
- [ ] 每个插件页面至少包含 1 张截图或 1 段录屏
- [ ] 提供插件分类索引（按功能域）和场景化导航（按使用场景）
- [ ] VitePress 站点成功部署到 GitHub Pages
- [ ] 文档模板可供后续插件更新时复用
- [ ] 站点支持中英文关键词搜索

## 约束条件

### 技术约束
- **静态站点生成器**：VitePress（Vue 生态，Markdown 驱动）
- **部署平台**：GitHub Pages（免费，自动部署）
- **截图工具**：phantom 插件（桌面自动化截图）
- **录屏工具**：scry 插件（终端录制、GIF 生成）
- **版本控制**：Git + GitHub
- **CI/CD**：GitHub Actions 自动构建部署

### 资源约束
- **团队**：个人项目
- **时间**：质量优先，无硬性截止日期
- **预算**：零预算（全部使用免费服务）

### 集成要求
- 必须与 GitHub 仓库集成（源码托管 + Pages 部署）
- phantom 和 scry 插件需在本地环境可用
- 文档内容需 Markdown 格式，兼容 VitePress

## 方案对比

### 方案 A：纯手动编写
**优点**：完全可控，质量有保障
**缺点**：工作量极大（23 个插件 × 详细文档），媒体素材制作效率低，维护成本高
**风险**：容易半途而废，一致性难保证

### 方案 B：模板驱动 + 半自动化 ⭐ 选中
**优点**：
- 模板保证全站风格统一
- AI 辅助生成初稿 + 人工审核，兼顾效率和质量
- phantom/scry 脚本化批量制作媒体素材
- GitHub Actions 推送即部署
- 模板规范便于后续维护

**缺点**：需要前期投入时间设计模板和脚本
**风险**：模板设计不合理可能导致返工（缓解：先做 3 个插件验证模板）

### 方案 C：全自动文档生成
**优点**：速度快，自动化程度高
**缺点**：质量不可控，中文表达可能不自然，媒体素材无法自动生成
**风险**：生成的文档可能严重偏离用户需求

## 选择理由

选择方案 B（模板驱动 + 半自动化），核心理由：

1. **质量与效率平衡**：AI 辅助生成初稿大幅降低重复劳动，人工审核确保准确性和可读性
2. **可维护性**：模板规范使得插件更新时只需修改对应页面，无需重新设计
3. **一致性**：模板确保 23 个插件页面风格统一，用户体验连贯
4. **风险可控**：先用 3 个核心插件验证模板，确认后再批量展开

## 已接受的权衡

| 权衡 | 影响 | 缓解措施 |
|------|------|----------|
| 未使用 Docusaurus（功能更丰富） | 部分高级功能缺失（如版本管理、i18n 内置） | VitePress 更轻量快速，中文搜索可用本地插件，VitePress 1.x 已有 i18n 支持 |
| 需要学习 phantom/scry 用法 | 前期学习成本 | 这两插件本身就是文档内容的一部分，学习过程可产出案例 |
| 不包含自动检测插件更新的机制 | 插件更新后需手动同步文档 | 模板规范降低更新成本；后续可加入 GitHub Actions 定期检查 |
| 站点仅为静态文档 | 无用户反馈/评论功能 | 可后续集成 Giscus 评论系统 |

## 超出范围

- 不包含视频教程（仅截图 + GIF 录屏）
- 不包含英文版本（仅中文）
- 不包含交互式 Playground
- 不包含用户反馈/评论系统（初期不包含，可后续添加）
- 不自动检测插件版本更新
