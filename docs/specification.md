## 1. 概述

### 1.1 目的

为 Night Market 生态的 23 个 Claude Code 插件构建一套完整、一致、可维护的中文使用说明书站点，帮助中文用户快速了解、安装和使用每个插件。

### 1.2 范围

**包含（IN）：**
- 23 个插件的独立文档页面（概述、安装、命令参考、使用场景、实战案例、FAQ、相关插件）
- VitePress 静态站点框架搭建
- 插件分类索引页（按功能域分类）
- 场景化导航页（按使用场景推荐插件组合）
- 全局中英文关键词搜索
- 每个页面至少 1 张截图或 1 段终端录屏
- GitHub Actions 自动构建 + GitHub Pages 部署
- 文档模板规范和维护指南

**不包含（OUT）：**
- 视频教程
- 英文版本
- 交互式 Playground
- 用户评论系统（初期不包含）
- 插件版本自动检测
- 后端服务 / 数据库

### 1.3 干系人

| 角色 | 关注点 |
|------|--------|
| Claude Code 中文用户 | 快速查找插件用法、命令参考、案例 |
| Night Market 插件开发者 | 文档一致性、可维护性 |
| 新用户 | 入门引导、场景化推荐 |
| 文档维护者 | 模板规范、更新流程 |

## 2. 功能需求

### 2.1 站点基础设施

---

### FR-001：VitePress 项目初始化

**描述**：使用 VitePress 搭建文档站点骨架，配置基础站点元数据、导航结构、主题样式。

**验收标准**：
- [ ] Given 空项目目录，when 执行 `npx vitepress init`，then 生成标准 VitePress 目录结构（`.vitepress/`, `index.md`, `package.json`）
- [ ] Given VitePress 配置，when 运行 `npm run docs:dev`，then 本地开发服务器正常启动，可通过浏览器访问
- [ ] Given 站点配置，when 打开首页，then 显示 NightMarket 品牌名称、Logo、简介
- [ ] Given VitePress 配置，when 构建站点，then `npm run docs:build` 成功生成静态文件到 `.vitepress/dist/`

**优先级**：高
**依赖**：无
**预估工作量**：S

---

### FR-002：导航结构配置

**描述**：配置站点顶部导航栏（Navbar）和侧边栏（Sidebar），支持插件分类浏览。

**验收标准**：
- [ ] Given 站点配置，when 访问任意页面，then 顶部导航栏显示「首页」「插件索引」「场景导航」「关于」四个入口
- [ ] Given 插件分类体系，when 展开侧边栏，then 按功能域分组显示全部 23 个插件链接
- [ ] Given 当前浏览的插件页面，when 查看侧边栏，then 当前页面对应的链接高亮显示
- [ ] Given 移动端设备（< 768px），when 访问站点，then 导航自动折叠为汉堡菜单

**优先级**：高
**依赖**：FR-001
**预估工作量**：S

---

### FR-003：插件分类索引页

**描述**：首页或独立页面展示所有插件的分类卡片式索引，每个卡片包含插件图标、名称、一句话描述、标签。

**验收标准**：
- [ ] Given 访问插件索引页，when 加载完成，then 按 9 大功能域分组显示 23 张插件卡片
- [ ] Given 插件卡片，when 渲染，then 每张卡片包含：插件名称、一句话中文描述、所属分类标签
- [ ] Given 插件卡片，when 点击，then 跳转到对应插件详细文档页
- [ ] Given 插件索引页，when 页面渲染，then 每个分类组显示该组包含的插件数量

**优先级**：高
**依赖**：FR-001, FR-002
**预估工作量**：M

---

### FR-004：场景化导航页

**描述**：独立页面按典型使用场景组织插件推荐，帮助用户根据「我想做什么」找到正确的插件组合。

**验收标准**：
- [ ] Given 访问场景导航页，when 加载完成，then 显示 8 个使用场景的卡片式布局
- [ ] Given 场景卡片，when 渲染，then 包含：场景名称、场景描述、推荐插件列表（含跳转链接）、典型工作流程图
- [ ] Given 用户在新项目开发场景，when 查看推荐，then 看到 attune → spec-kit → sanctum 的推荐流程及每个插件的作用说明
- [ ] Given 场景导航页，when 移动端访问，then 卡片自适应为单列布局

**优先级**：中
**依赖**：FR-003
**预估工作量**：M

---

### FR-005：全局搜索功能

**描述**：站点支持中英文关键词全文搜索，用户可快速定位到相关插件或命令。

**验收标准**：
- [ ] Given 用户点击搜索框或按 `Ctrl+K`，when 输入中文关键词（如"代码审查"），then 返回相关插件页面和内容片段
- [ ] Given 搜索框，when 输入英文关键词（如"attune"），then 同样返回匹配结果
- [ ] Given 搜索结果，when 渲染，then 每条结果显示页面标题和匹配内容预览
- [ ] Given 搜索结果，when 点击某条结果，then 跳转到对应页面并定位到匹配内容

**优先级**：中
**依赖**：FR-001
**预估工作量**：S

---

### FR-006：响应式布局

**描述**：站点在桌面端和移动端均有良好的阅读体验。

**验收标准**：
- [ ] Given 桌面端浏览器（≥ 1280px），when 访问任意页面，then 显示侧边栏 + 内容区双栏布局
- [ ] Given 平板端（768px-1279px），when 访问任意页面，then 侧边栏可折叠，内容区自适应宽度
- [ ] Given 手机端（< 768px），when 访问任意页面，then 侧边栏隐藏，内容独占全宽，代码块可横向滚动
- [ ] Given 任意设备，when 查看包含截图的页面，then 图片不超出屏幕宽度，支持点击放大

**优先级**：中
**依赖**：FR-001
**预估工作量**：S

### 2.2 插件文档内容

---

### FR-007：统一文档模板

**描述**：所有 23 个插件页面遵循同一套文档结构模板，确保风格一致。

**验收标准**：
- [ ] Given 任意插件文档页，when 查看结构，then 包含以下章节（按顺序）：
  - 概述（插件简介、核心能力、适用场景）
  - 安装（安装命令）
  - 命令参考（命令表格：命令 | 参数 | 说明 | 示例）
  - 使用场景（≥ 2 个场景，每个包含问题/解决/示例）
  - 实战案例（≥ 2 个案例，含操作步骤和截图/录屏）
  - 常见问题（≥ 3 个 FAQ）
  - 相关插件（配合使用 + 替代方案）
- [ ] Given 模板结构，when 新增插件页面，then 可通过复制模板文件快速开始
- [ ] Given 所有插件页面，when 批量检查，then 100% 的页面包含全部必需章节

**优先级**：高
**依赖**：无
**预估工作量**：M

---

### FR-008：插件概述章节

**描述**：每个插件页面以清晰的概述开头，让用户 30 秒内了解插件价值。

**验收标准**：
- [ ] Given 插件概述，when 阅读，then 2-3 句话说明插件是什么、解决什么问题
- [ ] Given 核心能力列表，when 展示，then 以项目符号列出 3-5 项关键能力
- [ ] Given 适用场景，when 展示，then 列出 3-5 个该插件最适用的场景
- [ ] Given 概述章节，when 渲染，then 在页面顶部、导航下方可见（above the fold）

**优先级**：高
**依赖**：FR-007
**预估工作量**：S（模板定义后，每个插件填充内容）

**描述**：提供准确的安装命令和前置条件说明。

**验收标准**：
- [ ] Given 安装章节，when 展示，then 包含安装命令的代码块（可直接复制）
- [ ] Given 有前置依赖的插件，when 展示安装说明，then 明确列出前置条件和依赖安装步骤
- [ ] Given 安装命令，when 用户复制粘贴执行，then 在标准 Claude Code 环境中可成功安装
- [ ] Given 安装章节，when 查看，then 包含验证安装成功的方法

**优先级**：高
**依赖**：FR-007
**预估工作量**：S

### FR-010：命令参考章节

**描述**：以表格形式列出插件的所有 Slash 命令、参数和用法示例。

**验收标准**：
- [ ] Given 命令参考表格，when 展示，then 包含列：命令 | 必需参数 | 可选参数 | 说明 | 使用示例
- [ ] Given 插件有多个命令，when 列出，then 按使用频率或逻辑顺序排列
- [ ] Given 命令示例，when 展示，then 使用代码块格式，包含实际可运行的命令
- [ ] Given 命令表格，when 在移动端查看，then 表格可横向滚动或自适应换行

**优先级**：高
**依赖**：FR-007
**预估工作量**：S

### FR-011：使用场景章节

**描述**：每个插件文档包含 ≥ 2 个典型使用场景，以「问题 → 解决 → 示例」结构展开。

**验收标准**：
- [ ] Given 使用场景章节，when 展开，then 每个场景包含：
  - **场景名称**：一句话概括
  - **问题描述**：用户面临的具体困境
  - **解决方案**：如何使用该插件解决
  - **命令示例**：可复制的实际命令
- [ ] Given 插件页面，when 检查，then 至少包含 2 个使用场景
- [ ] Given 场景描述，when 阅读，then 语言通俗、面向实际任务，非纯技术罗列

**优先级**：高
**依赖**：FR-007
**预估工作量**：M

### FR-012：实战案例章节

**描述**：每个插件文档包含 ≥ 2 个完整的实战案例，附带操作步骤和媒体素材。

**验收标准**：
- [ ] Given 实战案例章节，when 查看，then 每个案例包含：
  - 案例背景（真实或仿真的项目场景）
  - 完整操作步骤（逐步说明）
  - 预期输出或结果
  - 至少 1 张截图或 1 段终端录屏
- [ ] Given 插件页面，when 检查，then 至少包含 2 个实战案例
- [ ] Given 案例中的命令，when 用户跟随操作，then 在标准 Claude Code 环境中可复现
- [ ] Given 案例中的媒体素材，when 查看，then 图片清晰可读（≥ 800px 宽），GIF 流畅（≥ 15fps）

**优先级**：高
**依赖**：FR-011, FR-014, FR-015
**预估工作量**：L

### FR-013：常见问题章节

**描述**：每个插件文档包含 ≥ 3 个常见问题及解答。

**验收标准**：
- [ ] Given FAQ 章节，when 渲染，then 使用可折叠的 accordion 样式或锚点导航
- [ ] Given 插件页面，when 检查，then 至少包含 3 个 FAQ
- [ ] Given FAQ 内容，when 阅读，then 问题覆盖：安装问题、常见错误、最佳实践
- [ ] Given 相似问题跨插件出现，when 查看 FAQ，then 不同插件的相同问题保持答案一致

**优先级**：中
**依赖**：FR-007
**预估工作量**：S

### FR-014：相关插件交叉引用

**描述**：每个插件页面底部列出相关插件信息，帮助用户发现插件间的协作关系。

**验收标准**：
- [ ] Given 相关插件章节，when 展示，then 分为两组：
  - **配合使用**：可协同工作的插件（含链接和一句话协作说明）
  - **替代方案**：功能类似的可选插件（含差异对比）
- [ ] Given 插件 A 引用了插件 B，when 点击链接，then 正确跳转到插件 B 的文档页
- [ ] Given 交叉引用链接，when 站点构建，then 所有内部链接有效（无 404）

**优先级**：中
**依赖**：FR-003
**预估工作量**：S

### 2.4 部署与自动化

---

### FR-018：GitHub Actions CI/CD

**描述**：配置 GitHub Actions 工作流，实现推送即构建、构建即部署。

**验收标准**：
- [ ] Given 推送到 main 分支，when CI 触发，then 自动执行：安装依赖 → 构建站点 → 部署到 GitHub Pages
- [ ] Given 推送到非 main 分支（PR），when CI 触发，then 执行构建验证但不部署（dry-run）
- [ ] Given 构建失败，when 检查，then GitHub Actions 日志清晰显示失败原因
- [ ] Given 部署成功，when 访问 GitHub Pages URL，then 站点可正常访问

**优先级**：高
**依赖**：FR-001
**预估工作量**：S

---

### FR-019：构建验证

**描述**：CI 流程中包含自动化质量检查。

**验收标准**：
- [ ] Given 推送到任意分支，when CI 运行，then 自动检查：
  - 无死链（broken links）
  - 所有图片引用可解析
  - VitePress 构建无警告
- [ ] Given 检测到死链，when CI 运行，then 构建标记为失败并输出具体死链列表
- [ ] Given 检测到缺失图片，when CI 运行，then 输出警告（不阻塞构建）

**优先级**：中
**依赖**：FR-018
**预估工作量**：S

### 2.5 内容质量

---

### FR-020：中文内容质量标准

**描述**：所有文档内容遵循中文技术写作规范。

**验收标准**：
- [ ] Given 任意文档页面，when 检查，then 中文表述通顺、无语病、无错别字
- [ ] Given 技术术语，when 使用，then 保持英文原名（如 plugin、slash command、hook），不强行翻译
- [ ] Given 代码块和命令，when 展示，then 保持原文不翻译
- [ ] Given 中英文混排，when 查看，then 英文单词前后有空格（如「使用 Claude Code 插件」）
- [ ] Given 标点符号，when 检查，then 中文内容使用全角标点，英文内容使用半角标点

**优先级**：中
**依赖**：无
**预估工作量**：M（贯穿整个编写过程）

---

**优先级**：低
**依赖**：FR-007, FR-018
**预估工作量**：S

**依赖**：FR-007

## 3. 非功能性需求

### NFR-001：性能

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 首页加载时间（LCP） | < 2 秒 | Lighthouse 评分 ≥ 90 |
| 插件页面加载时间 | < 1.5 秒 | Lighthouse 评分 ≥ 90 |
| 搜索响应时间 | < 500ms | 手动测试 |
| 构建时间（全站） | < 60 秒 | CI 日志 |
| 页面总大小（含资源） | < 500KB/页 | Chrome DevTools |

### NFR-002：可访问性

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 色彩对比度 | WCAG AA 级 | Lighthouse Accessibility ≥ 90 |
| 键盘导航 | Tab 键可遍历所有交互元素 | 手动测试 |
| 语义化 HTML | 页面使用恰当的标题层级 | 自动化检查 |
| 图片 Alt 文本 | 100% 图片有描述性 Alt | 自动化检查 |

### NFR-003：可靠性

- VitePress 构建成功率：> 99%
- GitHub Pages 可用性：依赖 GitHub（SLA 99.9%+）
- 死链检查每 PR 执行，构建失败阻塞合并
- 媒体文件丢失不阻塞构建（降级为占位提示）

### NFR-004：可维护性

- 文档与模板分离：修改模板不影响已有内容（除非结构变更）
- 插件页面独立：修改 A 插件不影响 B 插件
- 配置文件集中：导航、侧边栏配置集中管理
- 媒体素材可替换：替换截图/GIF 只需替换文件，无需修改 Markdown

### NFR-005：兼容性

| 浏览器 | 最低版本 |
|--------|----------|
| Chrome | 最新 2 个主版本 |
| Firefox | 最新 2 个主版本 |
| Safari | 最新 2 个主版本 |
| Edge | 最新 2 个主版本 |
| 移动端 Safari | iOS 15+ |
| 移动端 Chrome | Android 10+ |
